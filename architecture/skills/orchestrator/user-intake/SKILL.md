# User Intake

## When to Use

Используй только при прямом новом запросе пользователя до backlogging и task
separation. Не используй для task, которая уже находится в `architecture/tasks/`.

## Workflow

1. Прими текстовое описание пользователя и все приложенные изображения.
2. Для каждого изображения выдели UI-зоны и их назначение.
3. Для каждой зоны перечисли все наблюдаемые controls:
   - кнопки и menu actions;
   - поля ввода и их видимый тип;
   - поля выбора, checkboxes и переключатели;
   - таблицы, графики, labels, статусы и другие отображаемые данные.
4. Зафиксируй для каждого элемента его видимый label, расположение, доступное
   состояние и наблюдаемое действие. Не придумывай невидимые API, validation
   rules или поведение.
5. Дополняй visual inventory только прямыми требованиями словесного описания
   пользователя. При противоречии текст пользователя имеет приоритет над
   изображением; противоречие записывается явно.
6. Сохрани результат как законченное user TS в связанной `kind: idea`
   task-записи со статусом `backlog`:
   цель, зоны, элементы, пользовательские действия, scope и out of scope.
7. После фиксации user TS считай его исходным законом для дальнейшей работы.
   Недостающие продуктовые детали, defaults, transitions и MATLAB-аналогии
   запрашивай у MATLAB Researcher через numbered handoff, а не выводи сам.

## Output

User-intake handoff должен содержать:

- исходный текст и ссылки на изображения;
- inventory зон;
- inventory controls по зонам;
- прямые словесные требования;
- выявленные противоречия и пробелы;
- зафиксированный scope/out of scope;
- handoff для MATLAB Researcher с вопросами только по отсутствующим деталям.

Изменить зафиксированное user TS может только новый явный запрос пользователя.
